# 중복 영수증 눈으로 비교 후 확정 (Duplicate compare)
- 상태: shipped (2026-07-28)
- 대상: cardconv (OCR 스테이징 단계)

## 문제

신규 업로드가 기존 원장 영수증과 중복으로 판정되면(`dup_hint='ledger'`), 스테이징 카드에 빨간 배지 **"⚠ Already in Ledger?"** 가 뜨고 체크가 해제된 채 `🗑 Discard` 버튼이 붙는다. 확인 절차는 브라우저 `confirm()` **텍스트 한 줄뿐**이다.

강프로님이 판단하려면 필요한 정보가 화면에 하나도 없다:
- **어느** 원장 영수증과 겹치는지 모른다 (id도, 이미지도, 파일명도)
- 그 원장 영수증이 **AMEX 명세서의 어느 거래에 매핑돼 있는지** 모른다
- 두 영수증 사진을 **나란히** 볼 수 없다

판정 근거는 `(금액, 상호)` 버킷 + 날짜/시간 호환성뿐이라 오탐이 가능하다 — 같은 식당에서 같은 금액을 두 번 결제한 실제 별건이 중복으로 잡힐 수 있다. 지금 구조에서는 그걸 **확인할 방법 없이** 버리거나 담게 된다.

## 목표

1. 중복 의심 카드에서 **비교 화면**을 열어 신규 vs 기존을 나란히 본다 — 사진, OCR 값, 그리고 기존 쪽의 **매핑 내역(매칭된 AMEX 거래 + 상태)**.
2. 보고 나서 **확정**한다 — 중복이면 신규를 버리고(tombstone), 별건이면 별건으로 표시하고 담는다.
3. 확정 결과가 무엇을 건드리고 무엇을 안 건드리는지 화면에 분명히 쓴다.

## 비목표 (이번엔 안 한다)

- **원장 내부 중복 그룹**(`_mark_duplicates` / `dup-row` 접이식 행)은 손대지 않는다. 이번 범위는 **스테이징(신규) ↔ 원장(기존)** 뿐이다.
- 같은 배치 안의 중복(`dup_hint='staged'`)은 비교 화면 대상이 아니다 — 비교할 "기존 매핑"이 없다. 배지·Discard 현행 유지.
- 중복 판정 알고리즘(`_flag_staged_dups`)의 기준은 바꾸지 않는다.
- 이미지 확대/줌·회전 뷰어는 만들지 않는다 (기존 썸네일 확대 동작 재사용).
- 일괄 비교(여러 중복을 한 화면에서 순회)는 하지 않는다. 카드 단위 1:1.

## 사용자 흐름

1. Drive 동기화/업로드 → OCR 스테이징 화면에 카드가 뜬다
2. 중복 의심 카드에 배지 **⚠ Already in Ledger?** + 신규 버튼 **🔍 Compare**
3. Compare 클릭 → 비교 화면(모달) 열림. 좌 = 신규 업로드, 우 = 기존 원장 영수증
   - 양쪽: 사진, 날짜, 상호, 인쇄금액, 손글씨금액, 최종금액, 카드타입
   - 기존 쪽만: **상태 칩**(matched/unmatched/pending), **매핑된 거래**(날짜·vendor·금액), 원장 열기 링크
   - 값이 다른 행은 시각적으로 표시(같으면 조용히 둔다)
4. 두 가지 확정 중 하나:
   - **Same purchase — discard this scan** → 신규를 큐에서 제거 + tombstone(재동기화로 안 돌아옴). **원장 행은 그대로.**
   - **Different purchase — keep both** → 신규에 `dup_exempt=true` 설정, 체크박스 자동 체크, 배지 제거
5. 모달 닫히고 카드가 갱신된다 (전체 리로드 없이)

## 데이터

- 건드리는 파일: `~/.appdata/cardconv/ocr_staging_<data_key>.json`, `receipts_<data_key>.json` (읽기)
- **신규 키: 없음.** `dup_exempt`는 이미 존재하는 키(`_migrate_entry` 기본값 `False`)를 스테이징 엔트리에도 그대로 쓴다.
- `_flag_staged_dups`가 현재 `dup_hint`(문자열)만 남긴다 → **`dup_match_ids`(list[str], 기본 `[]`)를 메모리상 주석으로 추가**. 저장하지 않고 렌더 시점에만 계산하므로 스키마 변경 아님.
- 마이그레이션: **없음.** 기존 스테이징 파일은 `dup_match_ids` 없이도 그대로 읽힌다(렌더 때 계산).
- 롤백: 새 코드가 저장하는 값이 없으므로 구버전으로 되돌려도 데이터 무손상.

## 영향 표면

- **원장 탭**: 영향 없음 (기존 행 읽기만)
- **export(xlsx·SAP)**: 영향 없음 (확정 결과는 기존 discard/`dup_exempt` 경로와 동일)
- **🪦 Discarded 목록**: discard 확정 시 기존과 동일하게 tombstone으로 들어감 — Restore도 그대로 동작해야 함
- **모바일 390px**: 좌우 2열이 들어가지 않음 → **세로 스택**(신규가 위, 기존이 아래)
- **라이트 테마**: 차이 강조 색은 토큰만 사용
- **권한/멀티테넌트**: 비교 대상 원장 조회는 반드시 같은 `data_key` + 같은 카드 프로필(`@pid`) 안에서만. 교차 조회 금지.

## 리스크 / 미결 질문

**결정됨 (2026-07-28 강프로):**
- **A1. 후보가 여러 건이면 전부 목록으로** 보여준다. 유력한 1건만 골라 보여주지 않는다 — 고르는 순간 판단이 우리 것이 된다.
- **A2. `dup_exempt=true`는 영구.** 원장에 들어간 뒤에도 중복 그룹에서 빠지는 것이 의도한 동작이다.
- **A3. completed 영수증은 후보에서 계속 제외** (현행 유지).
- **A4. 반대 방향(기존 삭제·신규 유지)은 이번 범위 밖.** 모달에 "원장에서 직접 삭제" 안내만 둔다.

## 검증 기록 (2026-07-28)

샌드박스(`WAYFINDER_DATA_ROOT` 격리, 실데이터 무영향)에 원장 120건 + 같은 금액·상호의
중복 후보 2건 + 신규 스캔 1건(손글씨 금액만 다르게)을 심어 브라우저로 실측.

- 배지 `⚠ Already in Ledger? (2)`, Compare 버튼은 그 카드에만 1개
- 사진 3장 모두 실제 디코드(4000x2252), Drive 끊김 시 `🧾 Preview unavailable` 폴백
- 매핑 표시 `2026-05-10 / SAN FRANCISCO GIANTS / $45.61`, 칩 `MATCHED` / `PENDING MATCH`
- 강조는 `Handwritten` 행만 (99.99 vs 없음)
- **discard**: 원장 120 → 120 불변, 스테이징 1 → 0, tombstone +1(`FAKE_UNIQUE_FID_001`)
- **keep both**: 배지·Compare 사라지고 체크 자동 활성, `dup_exempt=true` 저장
- 390px 1열 스택 + 바텀시트(radius 18px) + 버튼 44px + 가로스크롤 0, 라이트/다크 양쪽
- 중복 아닌 카드의 Discard 정렬 불변(양쪽 우측 12px), JS 에러 0

기존 테스트가 잡은 회귀: id 없는 레거시 원장 행에서 중복 경고가 사라지던 것 → 경고는
