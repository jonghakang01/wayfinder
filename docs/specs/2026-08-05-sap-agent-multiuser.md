# 출장비 SAP 상신 자동화 — 다중 유저 (PC 에이전트 + 서버 큐)
- 상태: draft
- 대상: cardconv (Review·설정·export), 신규 PC 에이전트, scripts/sap_trip_robot.py(대체 예정)

## 문제

출장비는 **엑셀 일괄 업로드가 없다**(강프로 확인 2026-08-05). 일반 경비처럼 파일 하나로 올릴 수 없어 건별로 GTE 화면에 타이핑해야 한다. 지금 그 타이핑을 로봇이 하고 있지만, **강프로님 PC 한 대에만 성립하는 조립품**이다. 다른 유저에게 주려면 세 가지가 막힌다.

### 확인한 사실 (근거 표기)
- ✓ **SAP 신분이 코드에 박혀 있다.** `FIXED = {employee_id: 20170321, payee: "A0016672", cost_center: "AG010238"}` (`_cardconv_core.py:159` 직접 읽음)이 **세 내보내기 경로 전부**(일반 xlsx `:1748`, Ledger xlsx `:4887`, 출장 JSON `:4606`)에서 쓰이고 유저별 재정의가 **한 군데도 없다**. 지금 다른 유저가 내보내면 강프로님 사원번호로 상신된다. cardconv 실사용 계정은 이미 여러 개다(convtest·h.hwang2·lauren.lee 등, ✓ prod 데이터 파일 목록).
- ✓ **로봇이 기계별 조각 6개에 의존한다.** WSL+playwright(+`LD_LIBRARY_PATH` chromium 라이브러리 우회), `C:\Temp\EdgeSAPRobot` 프로필 Edge, WSL↔Windows TCP 중계기(`cdp_relay.py`), `wayfinder-robot://` HKCU 프로토콜, 보안 에이전트 회피용 예약작업 `SAPRobot`, 하드코딩 경로 `C:\Users\Jongha Kang\Downloads`.
- ✓ **로봇의 보고가 강프로님 실사용에 닿지 않는다.** Downloads의 실제 export(`trip_submit_..._2026-08-04 (1).json`)의 tx_id 4건이 **prod에 4/4, 로컬에 0/4** — 즉 prod 화면에서 내려받아 쓰신다. 로봇이 남기는 `/tmp` 파일은 prod 서버가 볼 수 없으므로 되쓰기·배지가 원리적으로 작동하지 않는다.
- ✓ GTE는 각자의 SSO 세션에서만 열린다 → **타이핑하는 손은 각 유저 PC에 있어야 한다**(서버가 전 직원 로그인을 대신 들 수 없다).
- ✓ WSL/PC에서 prod로 HTTP 통신 가능(200 확인) → 에이전트가 서버에 보고하는 구조는 성립한다.

## 목표

- 유저가 Review에서 **"Submit to SAP"를 누르면**, 자기 PC의 에이전트가 자기 GTE에 건별로 기입하고, 결과가 **서버 화면에 돌아온다**(로컬이든 prod든 동일).
- 각 유저가 **자기 사원번호·코스트센터로** 상신한다. 남의 신분으로 나가는 경로를 없앤다.
- 새 유저는 **실행파일 하나 + 토큰 한 번**으로 시작한다(WSL·파이썬 설치 없음).

## 비목표 (이번엔 안 한다)

- MSI/설치 마법사, 자동 업데이트 — 실행파일 + 한 장 안내로 시작한다.
- Edge 외 브라우저 지원.
- GTE 메뉴 트리 자동 항해(유저가 상신 화면을 열어두고, 에이전트는 그 화면을 잡는다). URL 직행은 Phase 4 후보.
- SAP 쪽 영수증 이미지 첨부.
- 일반 경비(xlsx) 경로의 자동화 — 이미 파일로 올리므로 그대로 둔다.
- 여러 유저의 작업을 서버가 동시에 조율하는 스케줄러 — 유저당 한 번에 한 작업.

## 구조 — 서버는 머리, PC 에이전트는 손

지금 로봇이 혼자 하는 일을 둘로 쪼갠다. 핵심 전환은 **"Downloads의 파일을 로봇이 집어간다" → "서버의 작업을 에이전트가 받아간다"**.

| | 현재 | 제안 |
|---|---|---|
| 작업 전달 | 브라우저가 JSON을 Downloads에 내려주고 로봇이 최신 파일 추측 | 에이전트가 서버에서 **작업을 받는다** |
| 신분 | 코드에 박힌 강프로님 값 | 서버의 **유저별 SAP 프로필** |
| 결과 보고 | PC의 `/tmp` 파일 (prod가 못 봄) | 에이전트가 **서버에 POST** |
| 인증 | 없음(로컬 파일) | **유저별 에이전트 토큰** |
| 브라우저 구동 | WSL playwright → 중계기 → Edge | 에이전트가 **같은 PC의 Edge에 CDP 직결**(중계기 불필요) |

이 전환이 부수적으로 없애는 것: 최신 파일 추측, 24시간 지난 export 경고, 카드 프로필 불일치, Downloads 경로 하드코딩, WSL↔Windows 경계.

## 사용자 흐름

1. (최초 1회) 유저가 `/cardconv` 설정에서 **SAP 신분**(사원번호·코스트센터·payee)을 넣고, **에이전트 토큰**을 발급받아 에이전트에 한 번 붙여넣는다.
2. 유저가 자기 PC에서 에이전트를 실행한다(로그온 시 자동 시작 권장). 에이전트는 서버에 몇 초 주기로 "나 여기 있다 + Edge/화면 상태"를 보고한다.
3. Review에서 출장 행을 골라 **Submit to SAP** → 서버가 그 유저의 작업을 만든다(행·금액·G/L·D/O·SAP 신분 포함).
4. 에이전트가 작업을 받아 GTE 상신 화면을 찾고(없으면 "화면을 열어주세요" 상태 보고) 건별로 기입·저장한다.
5. Review 화면에 **에이전트 상태·진행(2/4)·결과(✅ 4/4 / ⚠ 사유)** 가 뜨고, 저장된 행은 자동으로 **In progress**가 된다.

## 데이터

**유저별 SAP 프로필 (신규)** — `~/.appdata/cardconv/sap_profile_<user>.json`
- `{employee_id: int, payee: str, cost_center: str, updated_at: iso}`
- 마이그레이션: 없음. 파일이 없으면 **미설정**으로 취급.
- 강프로님 계정만 현재 `FIXED` 값으로 1회 시딩(기존 동작 유지).
- **미설정 유저의 내보내기·상신은 막는다**(남의 사원번호로 나가는 것보다 못 나가는 게 낫다).

**에이전트 토큰 (신규)** — `~/.appdata/cardconv/agent_tokens.json`
- `{<token>: {user, pkey, created_at, last_seen}}` — 용도 한정(작업 수령·상태 보고·결과 보고만).
- 재발급 시 이전 토큰 폐기. 로그인 세션과 별개.

**작업 큐 (신규)** — `~/.appdata/cardconv/agent_jobs_<user>.json`
- `{id, pkey, created_at, state: queued|running|done|failed, trip, lines[], progress{done,total}, results[]}`
- `lines[]` = 지금 트립 JSON의 줄 구조 + `vendor_kind`(75차) + SAP 신분.
- 마이그레이션: 없음(신규 파일).
- 롤백: 파일이 남아도 옛 코드는 읽지 않으므로 무해.

**기존 것 정리**
- `/tmp/wayfinder-robot-result.json` 통로는 **폐기**(에이전트 보고로 대체). 폐기 시점까지는 로컬에서 계속 동작.
- ✈ JSON 다운로드는 **수동 백업 경로로 유지**(에이전트 없이도 손으로 상신 가능해야 한다).

## 서버 API (토큰 인증, 신규)

- `GET  /cardconv/agent/job` → 대기 중 작업 1건 또는 `{}`
- `POST /cardconv/agent/state` → `{edge: bool, screen: bool, job_id?, progress?}` (하트비트, 몇 초 주기)
- `POST /cardconv/agent/result` → `{job_id, saved[], failures[]}` → 서버가 행을 In progress로
- `GET  /cardconv/robot/state` → 화면용(세션 인증): 에이전트 온라인 여부·Edge·화면·진행·마지막 결과

## 영향 표면

- Review 화면: Submit to SAP 버튼 + 상태/진행 표시(모바일 425px 포함)
- cardconv 설정: SAP 신분 입력 화면(신규), 토큰 발급
- **일반 xlsx·Ledger xlsx export**: `FIXED` → 유저 프로필로 전환(미설정 시 차단) — **기존 유저 동작이 바뀌는 지점**
- 권한·멀티테넌트: 작업·토큰 모두 `pkey`(로그인+카드 프로필) 스코프. 75차 사고의 교훈 그대로 적용
- prod/staging: 서버 측은 환경 무관하게 동작(에이전트가 어느 서버로 보고할지는 에이전트 설정)
- 기존 로봇 스크립트: Phase 3에서 에이전트로 대체, 그때까지 병존

## UX/UI

- 상태 표시 = 기존 `tk-chip`/스탯칩 셰이프, 색은 토큰. 새 컴포넌트 발명 없음.
- Submit to SAP = 기존 벌크액션 바(`rv-bulkbar`)에 버튼 추가.
- SAP 신분 설정 = 기존 폼 공유 컴포넌트.
- 영문 UI 카피.

## 단계 (각 단계가 그 자체로 쓸 만해야 한다)

- **Phase 1 — 통로 뒤집기 (1명, prod에서 동작).** 서버 큐 + 토큰 + 3개 API + 기존 WSL 로봇을 "작업을 받아와 보고하는" 형태로 개조. 이걸로 **지금 prod에서 안 되는 되쓰기·상태가 처음으로 실제 동작한다.**
- **Phase 2 — 신분 분리.** 유저별 SAP 프로필 + 미설정 차단 + 강프로님 값 시딩. 다른 유저가 잘못 상신할 경로를 닫는다.
- **Phase 3 — 배포 가능한 에이전트.** WSL 의존 제거(Windows 단일 실행파일, CDP 직결), 로그온 자동 시작, 파일럿 1명.
- **Phase 4 — 화면 완성.** 진행률·실패 사유·재시도, GTE URL 직행 검토.

## 수용 조건 (Phase 1)

- [ ] Review에서 Submit to SAP → 작업이 생기고, 에이전트가 받아 기입한다
- [ ] 저장된 행이 **prod 화면에서** In progress로 바뀐다(현재 불가능한 것)
- [ ] 에이전트가 꺼져 있으면 화면이 "에이전트 오프라인"이라 말하고 버튼이 작업을 만들지 않는다
- [ ] Edge는 떴지만 상신 화면이 없으면 그 상태가 화면에 표시된다
- [ ] 0건 저장이면 성공처럼 보이지 않는다(경고색 + 사유)
- [ ] 토큰 없이 API를 부르면 401, 남의 토큰으로 남의 작업을 못 받는다
- [ ] 카드 프로필이 다르면 작업이 섞이지 않는다
- [ ] 425px 가로 스크롤 0, 다크·라이트 정상
- [ ] pytest + smoke 통과

## 리스크 / 미결 질문

- **Q1. 다른 사람 PC에 실행파일을 배포하는 것이 회사 정책상 괜찮습니까?** 이건 제가 판단할 수 없습니다. 보안 에이전트가 콘솔을 죽이는 환경(✓ 실측)이라, 남의 PC에서는 IT 승인이나 예외 처리가 필요할 수 있습니다. **이 답이 Phase 3의 전제입니다.**
- **Q2. 파일럿 1명을 누구로 할까요?** 두 번째 PC에서 한 번 돌아야 "다중 유저"가 증명됩니다. 강프로님 PC만으로는 알 수 없습니다.
- **Q3. SAP 신분(사원번호·코스트센터·payee)을 유저가 직접 입력할까요, admin이 대신 넣을까요?** 틀리면 남의 이름으로 상신되므로, 저는 **admin 승인**을 권합니다(유저가 입력 → admin이 확인 표시).
- **Q4. 에이전트를 로그온 시 상시 실행으로 둘까요?** 상시면 버튼이 즉시 동작합니다. 필요할 때만 실행이면 "먼저 에이전트를 켜세요" 단계가 남습니다. 저는 상시를 권합니다.
- **Q5. Edge 전용 프로필(현재 방식, Knox 재로그인 1회)을 유지할까요?** 유저의 기본 Edge에 디버그 포트를 붙이면 재로그인이 없지만, 디버그 포트가 열린 브라우저로 평소 업무를 하게 됩니다. 저는 **전용 프로필 유지**를 권합니다.
- **R1.** 금융 시스템에 자동 입력하는 도구를 남에게 주는 것 자체의 리스크. 완화책: 작업은 명시적 클릭으로만 생성, 건별 저장 검증(그리드 Total), 실패는 건너뛰고 사유 기록, 상신 후 상태는 항상 사람이 확인할 수 있게 화면에 남긴다.
- **R2.** GTE 화면 구조가 바뀌면 전 유저가 동시에 멈춘다. 완화책: 셀렉터를 서버에서 내려주는 설정으로 두면 에이전트 재배포 없이 고칠 수 있다(Phase 3에서 검토).
