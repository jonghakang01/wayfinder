# Toast Companion 2차 개편 — 자리 중심 플로우 · 계정별 서버 저장 · 모음집 300
- 상태: approved (2026-08-01 강프로 — 3탭·품질우선 300·로그인 필수 모두 동의)
- 대상: toast (`/toast`, services/toast.py + toast_assets/)

## 문제
(2026-08-01 강프로 피드백)
1. 자리 만들기와 특성(설정) 칩이 별개 표면에 있어 흐름이 끊긴다 — 자리를 만들어도 뽑기까지 한 번 더 가야 한다.
2. 자리·인물·저장 기록이 localStorage라 폰/PC가 따로 논다.
3. 핵심 가치는 생성형이 아니라 **검증된 건배사** — 현재 모음집 119건으로는 상황 커버리지가 얕다.

## 목표
- 자리 등록이 곧 시작점: **자리 만들기(특성 포함) → 저장과 동시에 1차 건배사 자동 제안**.
- 자리 성격 = 칩 다수선택 유지 + **자유 한 줄 입력** 추가(생성·제안에 반영).
- 기록(자리·인물·저장함·heard)이 **로그인 계정에 저장**되어 폰/PC 어디서나 동일.
- 모음집 **300건 목표** 확장(전 건 태그·출처 표기, 품질 우선).

## 비목표 (이번엔 안 한다)
- 사전 브리핑 UI 복원 (코드 보존 상태 유지)
- 계정 간 공유·팀 기능 (내 계정 = 내 기록만)
- 오프라인 PWA / 아침 알림
- 생성형 품질 개선 (모음집이 우선, 생성형은 현행 유지)

## 사용자 흐름
1. `/toast` 진입 → 오늘 자리 있으면 그 자리 + 제안 카드, 없으면 "자리 만들기"가 첫 동작
2. 자리 만들기 시트 = 이름·참석자 + **특성 칩(6종 다수선택) + 자유 한 줄** 한 화면
3. 저장 → 자동으로 1차 뽑기 실행(📖 정석 3 + ✨ 생성형 혼합, 재탕 배지 포함)
4. 이후 재뽑기·모음집 탐색·낭독·🍻 기록은 현행 유지 — 기록은 서버로

## 데이터
- 신규: `DATA_ROOT/<user>/toast.json` — `{events, people, saved, settings}` (momentum과 동일 per-user 패턴, ctx["user"])
- API 신규: `GET/PUT /toast/api/state` (전체 로드/저장, updated_at 포함)
- 마이그레이션: 첫 로드 시 서버 state가 비어 있고 localStorage에 기존 데이터가 있으면 **클라이언트가 1회 업로드** 후 localStorage는 백업으로 유지(삭제 안 함)
- 충돌: last-write-wins (updated_at 비교, 동시 편집은 비목표)
- 롤백: 구 코드로 돌아가도 localStorage 백업이 있어 기존 기기에서는 동작
- canon.json: 119 → 300 목표, 스키마 불변(항목·occ·role·tone·신선도·pop). `_meta.updated` 갱신

## 영향 표면
- 홈 메뉴·라우트: 변경 없음 (/toast 유지)
- 권한: 로그인 필수화(계정별 저장의 전제) — 기존 auth 상속 확인
- 모바일 390/425px: 자리 만들기 시트에 칩+한줄 추가되므로 재검증
- export/딥링크/알림: 영향 없음

## UX/UI
- 자리 만들기 시트 = 기존 바텀시트 재사용, 칩 패턴은 6차 피드백의 참석자 칩과 동일 문법
- 새 패턴 발명 없음

## 수용 조건
- [ ] 자리 저장 직후 사용자 조작 없이 제안 카드가 뜬다
- [ ] 자유 한 줄 입력이 생성 프롬프트·모음집 필터에 반영된다
- [ ] PC에서 만든 자리·저장함이 폰(같은 계정)에서 보인다
- [ ] 기존 localStorage 기록이 첫 로드 후 서버에 나타난다 (유실 0)
- [ ] canon ≥ 300건, 전 건 태그 완비, 중복 0 (기계 검사)
- [ ] 빈 상태(자리 0)에서 "자리 만들기" 유도가 첫 화면
- [ ] 425px 가로 스크롤 0, pytest + smoke 통과

# v2.1 추가: 광고주 뉴스 브리핑 탭 (2026-08-01 강프로 지시)
- 상태: approved (2026-08-01 — "앱 오픈 시 백에서 1회 리프레시, 수동 리프레시로 강제 갱신" 수정 반영, 그 외 이견 없음)
- 결정 완료: 위치=Toast 안 탭 / 소스=Google News RSS 수집 + Claude 요약 (강프로 픽커 답변)
- 갱신 정책: 앱 오픈 → 등록된 전 유닛을 백그라운드 워밍(30분 넘게 묵은 것만 재수집·재요약, 화면 안 막음) / 카드 ↻ = 강제 갱신 / 그 외 조회는 12h 캐시

## 문제
광고주 만찬 전 그 회사 근황(뉴스)을 따로 검색해 봐야 한다. 대화 소재·건배사 재료가 되는
정보인데 앱 안에 없다.

## 목표
- Toast에 **광고주 탭** 추가 (오늘 / 모음집 / 광고주 / 기록 4탭).
- 광고주를 등록·관리하고(기본 시드: 삼성, 한국타이어), 광고주 아래 **유닛**(삼성 US·브라질·중남미 같은 지역/법인)을 나눠 유닛별 뉴스를 따로 본다.
- 뉴스 = Google News RSS 헤드라인 수집 → Claude가 "무슨 일이 있고, 술자리에서 꺼낼 만한 포인트가 뭔지" 요약 카드 생성. 광고주·유닛별 캐시(12h)로 재방문은 즉시.

## 비목표
- 자동 주기 수집·푸시 알림 (온디맨드 + 캐시만)
- 뉴스 원문 저장·아카이브 (링크로 원문 이동)
- 사전 브리핑(Phase 3) 복원 — 단, 뉴스 카드가 나중에 그 재료가 될 수 있게 구조만 열어둠

## 사용자 흐름
1. 광고주 탭 → 광고주 칩(삼성 · 한국타이어 · ＋추가)
2. 광고주 선택 → 유닛 pill(전체 · US · 브라질 · ＋유닛) → 뉴스 요약 카드
3. 카드 = ①한 줄 상황 요약 ②포인트 3~5개(각각 "이게 왜 중요/자리에서 쓸 만한 한 마디") ③헤드라인 원문 링크 목록 ④수집 시각 + ↻ 새로고침
4. 광고주/유닛 추가 = 이름 + 검색어(자동 제안) + 지역(언어/국가) 선택

## 데이터
- `toast.json` state에 `clients:[{id, name, units:[{id, label, q, hl, gl}]}]` 추가 (계정별, 기존 state 동기화에 편승)
- 뉴스 캐시: `DATA_ROOT/toast/news_cache.json` — key=q|hl|gl, {summary, items, at}, TTL 12h (공용 캐시 — 뉴스는 계정 무관)
- API: `GET /toast/api/news?q&hl&gl(&refresh=1)` — RSS 수집(urllib, 외부 의존성 0) → Claude 요약 → 캐시
- 마이그레이션: clients 키 없으면 기본 시드 생성. 롤백 시 무해(모르는 키 무시)

## 영향 표면
- Toast 탭 1개 증가(4탭) — 425px에서 탭 폭 재검증
- 외부 네트워크 의존(news.google.com) — 실패 시 캐시 폴백 + 빈 상태 문구
