# Domestic/Overseas 구분(전 경로 공통) + 로봇 준비상태 표시
- 상태: **1번 주제 구현 완료**(2026-08-05, 로컬 검증까지) / 2번 주제(로봇 준비상태 배지)는 다음 회차
- 결정: Q1 되쓰기 = 넣는다, Q2 범위 = D/O 먼저 (강프로 2026-08-05)
- 대상: cardconv (Review 필터·행 편집, xlsx export, ✈ JSON export, 🤖), scripts/sap_trip_robot.py

## 배경 — 이 문서가 다시 쓰인 이유

초판(2026-08-04)은 Domestic/Overseas를 **출장(trip)별 속성**으로 봤다. 강프로 정정(2026-08-05):

> "지금 정해져 있는 Trip은 내가 테스트하려고 임의로 적용한 것이라 정확하지 않다. Trip명은 사용자가 확인하려고 구분한 것이니, Overseas냐 Domestic이냐는 **Trip명과 상관없이 통화를 기준으로** 정하는 게 확실하다. 이건 Trip이 아니라 **다른 일반 건들에도 적용되는 부분**이다."

따라서 이 문서의 1번 주제는 출장 기능이 아니라 **SAP로 나가는 모든 줄에 걸린 공통 필드**다.
초판의 "출장별 1회 선택"·"통화 다수결 제안"안은 폐기. 초판이 근거로 삼은 Korea Trip 통화 분포 분석도 태그가 임의값이라 폐기.

## 문제

1. **Domestic/Overseas가 두 경로에서 정반대로 하드코딩돼 있다.**
   - ✓ 일반 건 xlsx: F열 = `FIXED["domestic"]` = `"D"` **전 줄 고정** (`_cardconv_core.py:1738`, `:4647` 직접 읽음)
   - ✓ 출장 JSON→로봇: `select#hbrdCdu` 를 실행 인자 `--domestic` 유무로 전 줄 일괄 결정, 기본은 `"O"` (`sap_trip_robot.py:186,207`)
   - 같은 항목인데 한쪽은 전부 국내, 한쪽은 전부 해외로 나간다.
2. **통화도 하드코딩이다.** ✓ xlsx K열·JSON `currency` 모두 `FIXED["currency"]="USD"`. 줄이 실제 통화를 싣지 않는다.
3. **화면이 로봇 상태를 모른다.** 🤖는 콘솔만 띄우고 로봇은 최대 15분 대기한다. 준비됐는지·도는 중인지·끝났는지를 화면에서 알 수 없다. (초판 그대로)
4. **로봇이 저장해도 앱은 모른다.** ✓ NY Trip 4행이 로봇 1회차 성공 후에도 `status=open` (prod 데이터 직접 확인). ✓ 로봇 스크립트에 webapp 호출 코드 0건(grep). ✓ `in_progress`("SAP 상신 완료, 승인 대기") 상태와 설정 API는 이미 있음(`_handle_review_set_status`). ~ 그래서 같은 선택을 다시 export하면 GTE에 중복 상신될 것으로 추론 — 재실행으로 검증하진 않음(? 미검증).

## 판정 규칙 (강프로 확정, 2026-08-05)

- **최초 OCR 통화가 `USD` → Domestic(`D`)**
- **그 외 전부(KRW/INR/HKD/SGD/EUR…) → Overseas(`O`)**
- **통화가 없으면 → `D`** (기본값). 강프로가 화면에서 직접 뒤집을 수 있어야 함.

### 실측 (prod `transactions_jongha.kang.json` + 원장, ✓ 직접 집계)

| 통화 | 전체 1002행 | 열린 행 284행 |
|---|---|---|
| (없음) | 750 | 164 (58%) |
| USD | 187 | 56 |
| KRW | 42 | 42 |
| INR | 20 | 20 |
| HKD/SGD/EUR | 3 | 2 |

- ~ 통화가 빈 행은 대부분 외화 영수증이 안 붙은 AMEX 명세서 행으로 보임(코드 주석이 `ocr_currency`를 외화 영수증용이라 명시, 샘플 8건 모두 미국 가맹점). 그래서 기본 `D`가 다수와 맞는다.
- 위험: **KRW 결제인데 영수증이 안 붙은 행**은 통화가 비어 `D`로 잡힌다 → 수동 수정 경로(아래)가 이 위험을 받는다.

## 목표

- 모든 줄이 **자기 통화에서 유도된 D/O**를 갖고, xlsx·JSON 양쪽으로 **같은 값**이 나간다.
- 강프로가 Review에서 **행별로 D/O를 뒤집을 수 있다.**
- Review 상단에 **Kind 필터**가 있어 잘못 잡힌 것만 모아 고칠 수 있다.
- (2번 주제) 🤖 준비 상태와 결과를 화면에서 본다.

## 비목표

- 로봇을 웹에서 원격 실행하지 않는다. 트리거는 지금처럼 로컬 🤖.
- 실시간 진행률 스트리밍은 안 한다(시작·종료 두 시점만).
- 통화 자체를 새로 채우지 않는다(OCR 개선은 별건). 지금 있는 값으로만 판정한다.
- 여러 출장 동시 처리는 지금대로 하나씩.

## 데이터

**pool 트랜잭션 (`transactions_<user>.json` 의 `entries[]`)**
- 신규 키: `vendor_kind` — `null`(자동 판정) | `"D"` | `"O"`(수동 확정)
- 저장은 **덮어쓴 것만**. `null`이면 통화에서 매번 유도 → 나중에 영수증이 붙어 통화가 채워지면 자동으로 따라 바뀐다.
- 마이그레이션: 없음(없으면 `null`)

**export**
- xlsx F열: `FIXED["domestic"]` → **줄별 판정값**으로 교체 (일반 건 경로). Ledger xlsx의 같은 칸도 함께.
- 트립 JSON: 줄마다 `vendor_kind: "D"|"O"` + 판정 근거인 `receipt_currency` 추가
- **정정(2026-08-05 구현 중)**: 초안은 `currency` 하드코딩 USD를 실제 통화로 바꾸자고 했으나 **틀렸다.**
  ✓ 실 코드 확인 — 줄의 `amount`는 항상 USD 정산액이다(외화 영수증은 `usd_estimate`로 미러링됨,
  `_sync_cash_pool`). 금액이 USD인데 라벨만 KRW로 바꾸면 거짓 짝이 된다. 로봇은 `currency`를
  아예 쓰지도 않는다(✓ grep). → `currency`는 USD 유지, 영수증 통화는 별도 키로 싣는다.
- 롤백: 옛 로봇은 `vendor_kind`를 무시하고 `--domestic`을 쓴다 — 데이터 안 깨짐

**로봇**
- 줄의 `vendor_kind`를 그대로 따른다. 없으면 종전대로 `--domestic` 플래그.

## 사용자 흐름

1. Review 상단 필터에 **Kind**(All / Domestic / Overseas) 추가 — `Period / 검색 / Card / Usage / Sort` 옆
2. 각 행에 **D/O 표시**. 클릭(또는 인라인 셀렉트)으로 뒤집으면 그 행이 수동 확정(`vendor_kind`)됨
3. 수동으로 바꾼 행은 자동 판정과 구분되게 표시(자동으로 되돌리는 길도 있어야 함)
4. export(xlsx·JSON) 시 그 값이 그대로 실린다

## 되쓰기 구현 (Q1 = 넣는다)

- 로봇이 실제 저장한 줄의 `tx_id`를 `/tmp/wayfinder-robot-result.json`에 남긴다
  (`{at, user, trip, saved[], total}`)
- Review 렌더가 그 파일을 읽어 **열린 행만** `in_progress`로 넘기고 파일을 소비(삭제)한다.
  기존 self-heal 3종이 이미 렌더에서 도는 자리라 같은 관례를 따랐다.
- 로봇은 자기 세션이 없어서 API를 직접 못 부른다 → 파일이 통로. prod엔 이 파일이 아예 안 생긴다.
