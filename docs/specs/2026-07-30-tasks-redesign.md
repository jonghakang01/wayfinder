# Momentum Tasks 재설계 — 등록부터 관리까지

- 상태: approved (강프로님 2026-07-30 "일단 의도대로 해봅시다")
- 대상: momentum · Tasks 탭 (`services/todo.py`)

## 문제

**425px 실제 화면**에서 관찰한 것 (390px에서는 안 보였다 — 그래서 처음 진단이 빗나갔다):

할 일이 **0건인데 화면의 3분의 2가 관리 도구**다. 위에서부터 통계 3개 →
`+ New Group`(가장 크고 파란 버튼) → PROJECT 필터 → PRIORITY 필터 → Reset →
📍 Places → Ungrouped(0) → Completed(3) → `+ Task`(작은 회색) → Today's Habits.

1. **할 일 하나 적으려면 화면 3분의 2를 내려가야 한다.** `+ Task`가 맨 아래·작고·회색.
2. **가장 눈에 띄는 버튼이 엉뚱한 것을 가리킨다.** `+ New Group`은 폴더 만들기지 할 일 추가가 아니다.
3. **거를 게 없는데 필터가 화면을 먹는다.** 2026-07-29에 필터를 넣으면서 빈 상태 처리를 안 한 것 — 자초한 문제.
4. 데이터가 있을 때는 **한 줄에 컨트롤이 14개**(Done/Habit/group/priority/project/place/x). 17건이면 화면에 200개 넘게 뜬다.
5. **그룹과 프로젝트가 같은 말을 두 번 한다.** 새 할 일마다 "그룹이야 프로젝트야"를 정해야 한다.
6. 정렬이 마감일 순이라 **Low가 위에, High가 아래에** 섞인다. "뭐부터"에 답을 못 한다.
7. Tasks 탭 하단에 **Habits 섹션이 또** 있다(탭이 따로 있는데).

## 목표

1. 첫 화면 맨 위에서 **바로 적을 수 있다**.
2. 할 일이 없을 때는 **빈 화면이 비어 보인다**.
3. 목록을 훑을 때 **읽는 것만 보인다**. 고치는 건 눌러서 연다.
4. 맨 위에 **오늘 해야 할 것**이 온다.

## 비목표

- 메모 기능 제거 (prod 0건이지만 이번 범위 밖 — 등록 UI에서 눈에 덜 띄게만)
- 하위 작업, 반복 할 일, 담당자, 캘린더 뷰
- Habits 탭 자체의 개편 (Tasks 탭에서 중복 섹션만 제거)
- Today 탭 재설계

## 사용자 흐름

1. `/momentum?tab=tasks` → **맨 위 입력창**에 적고 엔터 → 바로 목록에 들어간다
2. 목록은 `지났거나 오늘 / 이번 주 / 나중 / 완료(접힘)`, 각 묶음 안에서 우선순위 높은 순
3. 줄을 누르면 **상세**가 열린다(모바일=아래에서 올라오는 시트, 데스크톱=인라인 확장)
4. 상세에서 프로젝트·우선순위·마감·장소·삭제

## 데이터

- **신규 키 없음.** 2026-07-29에 넣은 `project`/`priority`/`place_id`를 그대로 쓴다.
- **`group` → `project` 통합**: 마이그레이션은 읽을 때 수행 —
  `project`가 비어 있고 `group`이 있으면 `group`을 프로젝트로 읽는다. 저장 시 `project`에 기록.
  **prod 실측: 그룹 정의 0개, 그룹 지정 항목 0건** (todo를 쓰는 계정은 강프로님 하나) → 실제로 옮겨질 데이터가 없다.
- `task_groups.json`은 **지우지 않는다**(롤백 여지). 읽기만 멈춘다.

## 영향 표면

- `/todo/*` POST 17개: `/todo/add`에 project 추가 외 **경로·이름 불변**
- `/todo/group/add`·`/todo/group/delete`: 라우트는 남기되 UI에서 진입점 제거
- Today 탭(dashboard.py)이 `_load_todos`로 같은 파일을 읽음 → 키 변경이 없으므로 영향 없음
- 모바일 425px / 라이트·다크 / 대비 AA

## 리스크

- **R1. todo.py render는 큰 함수다.** 목록 렌더를 통째로 갈아끼우므로 JS 바인딩(드래그 정렬,
  인라인 폼 토글)이 깨질 수 있다 → 단계별로 425px에서 확인하며 진행.
- **R2. 드래그 재정렬(`/todo/reorder`)이 새 정렬과 충돌한다.** 자동 정렬이 생기면 수동 순서는
  의미가 사라짐 → 이번엔 드래그를 **끄고**, 필요해지면 "직접 정렬" 모드로 되살린다.
