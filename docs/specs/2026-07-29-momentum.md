# Momentum — Tasks/Habits/Overview 단일 앱 통합 + 업무툴화

- 상태: approved → 구현 완료 (강프로님 승인 2026-07-29: 통합=단일 라우트+탭, 업무툴=카테고리 이동+기능 추가+위치 알림, 장소=현재 위치 저장 버튼)
- 대상: todo · habits · dashboard → `/momentum`

## 문제

관찰된 사실:

- **홈에 같은 앱이 네 번 나온다.** `server.py:678`의 "My Productivity App" 진입
  카드 1개 + `CATEGORIES["🏠 개인"]`(server.py:516)의 `/dashboard` `/todo` `/habit`
  카드 3개. 진입 카드를 눌러도 실제로는 `/todo` 한 탭으로 갈 뿐이다.
- **세 앱은 이미 한 몸인데 세 개로 등록돼 있다.** `app_tabs()`(server.py:466)가
  세 페이지에 같은 탭바를 주입하고, `dashboard.py`는 `todo.json`과 `habits.json`을
  둘 다 읽는다. 그런데 `META["path"]`가 셋이라 홈·권한·PWA 바로가기가 전부 3중이다.
- **업무에 쓸 수 없다.** 할 일에 있는 필드는 `title/done/created_at/due_date`뿐이다.
  어느 프로젝트 일인지, 무엇부터 할지, 어디서 해야 하는지가 없다.
- 강프로님 요청(2026-07-29): "Task/습관 앱을 합쳐 하나로, 이걸 업무툴로 쓰겠다.
  홈에서 업무 카테고리로 옮기고, 업무 기능을 넣고, **위치 기반 알림**도 원한다."

## 목표

1. `/momentum` 하나로 들어가 Today/Tasks/Habits를 탭으로 오간다. 홈 카드도 1개.
2. 할 일에 **프로젝트·우선순위·마감**이 붙고, 그 축으로 걸러 본다.
3. 홈 "💼 업무" 카테고리에 자리한다.
4. 할 일에 **장소**를 붙이면, 그 장소에 도착했을 때 Telegram으로 알림을 받는다.

## 비목표 (이번엔 안 한다)

- **할 일과 습관의 데이터 모델 융합.** 탭은 합치되 `todo.json`/`habits.json`은
  그대로 둔다. ("반복 할 일 = 습관" 융합은 별건)
- **Deal Desk·Matter Tracker To Do 연동.** 강프로님이 이번 선택에서 고르지 않았다.
- 캘린더 뷰, 간트, 하위 작업(subtask), 담당자 배정, 협업/공유.
- 브라우저 백그라운드 위치 추적 (아래 "위치 알림" 참조 — 웹에서 불가능하다).
- 습관 쪽 기능 추가. 습관은 **탭으로 이사만** 하고 기능은 현행 유지.

## 사용자 흐름

1. 홈 "💼 업무"의 **⚡ Momentum** 카드 → `/momentum`
2. 기본 진입은 **Today** 탭 — 오늘 할 일 + 오늘 습관이 한 목록, 인라인 체크
3. **Tasks** 탭 — 프로젝트/우선순위/마감으로 거르고, 인라인으로 값을 바꾼다
4. **Habits** 탭 — 현행 습관 화면 그대로
5. 할 일에 장소를 붙여두면 → 폰이 그 장소에 도착할 때 Telegram으로 "여기서 할 일 3건"

## 데이터

건드리는 파일: `~/.appdata/<data_key>/todo.json`, `habits.json`(읽기만), 신규 `work_places.json`

**`todo.json` 신규 키** (전부 선택 — 없으면 기존과 똑같이 동작):

| 키 | 타입 | 기본값 | 뜻 |
|---|---|---|---|
| `project` | str | `""` | 자유 문자열. datalist로 기존 값 제안 |
| `priority` | int | `2` | 1=높음 2=보통 3=낮음 |
| `place_id` | str | `""` | `work_places.json`의 장소 id |

**신규 `work_places.json`** — 장소 목록:
```json
[{"id":"office","label":"오피스","lat":37.5665,"lon":126.9780,"radius_m":200}]
```

**마이그레이션: 없음.** 읽을 때 `t.get("project","")` 형태로 기본값을 준다.
기존 항목은 프로젝트 없음·보통 우선순위로 보인다.

**롤백**: 구코드는 모르는 키를 무시하고 그대로 읽는다. 단 **구코드로 저장하면
신규 키가 사라진다**(전체 배열을 다시 쓰므로). 롤백 시 손실은 신규 3키뿐이고
`title/done/due_date`는 안전하다.

## 영향 표면

- **홈 메뉴**: `CATEGORIES` 개인 3개 → 업무 1개(`/momentum`). 진입 카드(server.py:678) 제거.
- **기존 URL**: `/todo` `/habit` `/dashboard`는 **301이 아니라 302로 살려둔다**
  → `/momentum?tab=tasks|habits|today`. 폰 홈화면 바로가기·북마크가 이미 깔려 있다.
- **POST 엔드포인트**: `/todo/add` 등 11개, `/habit/*` 3개, `/dashboard/project/*` 3개는
  **경로를 바꾸지 않는다**(폼 action이 전부 여기 박혀 있음). 라우팅만 `/momentum`가 흡수.
- **권한**: `META["path"]`가 `/momentum` 하나가 되므로 `available_services`(settings.json,
  **환경 데이터라 배포되지 않음** — prod에서 따로 손봐야 함)와 기존 유저의
  `services` 목록에 `/todo`가 박혀 있다. → `has_service_access`에서 `/momentum`를
  구 3경로 중 하나라도 가진 유저에게 허용(호환 매핑).
- **PWA**: `manifest.json` shortcuts 2개(server.py:392) → `/momentum?tab=...`로 갱신.
- **알림**: Telegram 브릿지 재사용(신규 채널 없음).
- **모바일 390px / 라이트 테마**: 신규 UI 전부 대상.

## 위치 알림 — 실현 가능한 경로 (여기가 결정 지점)

**웹앱은 백그라운드에서 위치를 볼 수 없다.** 브라우저 Geofencing API는 폐기됐고,
Service Worker는 위치에 접근하지 못하며, Periodic Background Sync로도 불가능하다.
**"폰을 주머니에 넣은 채 회사에 도착하면 알림"은 PWA만으로는 만들 수 없다.**
(`? 미확인` 아님 — 웹 표준상 확정된 제약)

쓸 수 있는 세 가지:

| 안 | 방식 | 백그라운드 | 강프로님이 할 일 |
|---|---|---|---|
| **A. iPhone 단축어 자동화** | "도착 시" 자동화 → 서버 웹훅 호출 → Telegram 알림 | ✅ 진짜 됨 | 단축어 앱에서 자동화 1회 등록 |
| **B. Telegram 실시간 위치** | Telegram에서 위치 공유(8h) → 봇이 근접 감지 | ✅ 됨 | 가끔 위치공유 시작 버튼 |
| **C. 앱 열었을 때만** | `/momentum` 열면 현재 위치로 "여기서 할 일" 필터 | ❌ 알림 아님 | 없음 |

**권장: A + C.** A가 진짜 알림을 주고(단축어는 iOS에서 안정적), C는 앱을 열었을 때의
맥락을 준다. B는 위치공유를 매번 켜야 해서 실사용이 어렵다.

A의 서버 쪽은 작다: `POST /momentum/arrive` (토큰 인증) → 해당 장소의 미완료 할 일을
Telegram으로 발송. 기존 `tg-reply.sh`/브릿지를 그대로 쓴다.

## 구현 중 스펙과 달라진 것 / 추가한 것

- **id는 ASCII로 강제.** `"오피스".isalnum()`이 파이썬에서 True라 한글 라벨이
  그대로 id가 됐다. 폰 자동화에 타이핑해야 하는 값이므로 ASCII만 남기고
  아니면 `place-N`으로 떨어뜨린다.
- **하단 고정 요소가 탭 바를 덮고 있었다.** `.wf-back`과 테마 토글이
  `bottom:16px`이라 모바일 탭 바 안에 앉아 Today와 Habits 탭을 가렸다.
  탭 바가 있는 페이지에서는 위로 올린다. 토글은 인라인 스타일이라 CSS로
  못 밀어서 `.wf-theme-btn` 클래스로 뺐다(= `.wf-back`과 같은 처리).
- **`.group-select-inline` 모바일 높이 40 → 44px.** 이 클래스를 우선순위·장소
  피커가 함께 쓰게 되면서 가이드 미달 컨트롤이 늘어날 뻔했다.
- **모바일 행 액션은 2열로.** 컨트롤이 4개가 되어 한 줄에서 슬라이버로 찌그러졌다.
- **`send_text(code=200)`** 파라미터 추가 — 웹훅이 403/404를 내려야 해서.

- **이름은 Momentum, 경로는 `/momentum`** (강프로님, 2026-07-29). "Work Hub"는
  두 축을 나열하지도, 왜 한 앱인지 설명하지도 못했다. 할 일을 쳐내고 습관을
  이어가면 쌓이는 것이 이름이 됐다. 환경변수도 `MOMENTUM_ARRIVE_SECRET`.
- **좌표는 도착 판정에 쓰이지 않는다.** 지오펜스는 폰 오토메이션이 관리하고
  서버는 place id만 통보받는다 — `arrive()`는 label만 읽는다. 저장된 lat/lon은
  화면 표시용이며, 나중에 "앱을 열었을 때 여기서 할 일" 필터를 만들 때부터
  정확해야 한다. (HTTP origin에서는 브라우저 Geolocation이 막히므로 그때는
  좌표 수동 입력이나 prod HTTPS가 선행 조건.)
